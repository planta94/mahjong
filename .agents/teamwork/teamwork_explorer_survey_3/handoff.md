## 2. Logic Chain

1. **Rule System Grounding**:
   - Avalon is an information-asymmetry social deduction game. The game rules demand strict adherence to Don Eskridge's official player count distribution (5p: 3G/2E, 6p: 4G/2E, 7p: 4G/3E, 8p: 5G/3E, 9p: 6G/3E, 10p: 6G/4E).
   - In 7+ player games, Quest 4 requires 2 Fail cards to fail. This is mathematically crucial because Evil has 3 or 4 players; without the 2-fail requirement on Quest 4, Good's win probability drops below 20%.
   - The Vote Track ("Hammer") allows 5 consecutive proposal rejections per quest round. If the 5th proposal is rejected, Evil automatically wins. This forces Good to think critically and prevents indefinite proposal stalling.

2. **Role & Night-Vision Knowledge Derivation**:
   - Merlin must see all Evil players EXCEPT Mordred, but also sees Oberon.
   - Percival sees Merlin and Morgana, without knowing which is which.
   - Assassin, Morgana, Mordred, and Minions see each other, but DO NOT see Oberon.
   - Oberon sees nobody and is seen by no Evil player (though seen by Merlin).
   - Since network packets can be inspected via DevTools, the Host must NEVER send full role identities across P2P. Instead, the Host computes a seat-specific `nightVision: Map<number, NightVisionClue>` in `getPlayerView()`.

3. **Offline Communication & Privacy Shield UX Derivation**:
   - The user explicitly dictated: "offline from the game, the game dun handle communication".
   - The game UI acts as an authoritative, impartial, tamper-proof digital arbiter (board, secret quest voting terminal, Lady of the Lake adjudicator, and vote history tracker).
   - In couch / pass-and-play / hybrid table environments, adjacent players can shoulder-surf. A "Hold / Toggle-to-Peek Privacy Shield" is mandatory to conceal role cards, night-vision knowledge, and private Lady of the Lake results.

4. **Lady of the Lake (湖中仙女) Security Isolation**:
   - Lady of the Lake is usable after Quests 2, 3, and 4 by the current holder.
   - The loyalty (Good or Evil) is strictly revealed to the investigator only.
   - If broadcast to other clients, any player inspecting the network could cheat. Thus, `privateLadyResult` must ONLY be included in `getPlayerView(state, investigatorSeat)` and be `null` for all other seats.

5. **CSPRNG Fisher-Yates Quest Deck Shuffle**:
   - When quest cards are played, if they were sent in seat order, anyone inspecting network packets or timestamps could deduce who played Fail.
   - Therefore, the host gathers secret submissions, executes a CSPRNG Fisher-Yates shuffle, and only exposes the counts and shuffled array. Good players are structurally prevented from playing Fail (only Success is valid).

6. **Deduction AI Engine (Bayesian Trust & Role Simulation)**:
   - For Solo and Hybrid play (e.g. 1 human + 4-9 bots, or 3 humans + 2 bots), the bot must emulate intelligent deduction:
     - Maintains a `trustScores: Map<number, number>` in `[-1.0, 1.0]`.
     - Good bots dynamically downgrade players who propose or vote for failed quest teams.
     - Evil bots coordinate implicitly, avoid double-failing early quests, and protect Morgana/Mordred.
     - Percival bot analyzes proposals and votes of both candidates to disambiguate the true Merlin.
     - Assassin bot calculates a `merlinScore` across Good players, detecting players who voted with supernatural accuracy before quests failed, while filtering out Percival decoys.

## 3. Caveats

1. **Zero In-Game Chat Confirmation**: In accordance with user requirement Q9 ("offline from the game, the game dun handle communication"), no text-chat service or chat log input is included in the domain model or UI. All negotiation is verbal/offline.
2. **Lady of the Lake Claim Freedom**: When the Lady of the Lake holder investigates a player, the system reveals the true loyalty secretly to the holder. In offline communication, the holder is free to state the truth or lie verbally. The UI provides an optional "Claim Loyalty" toggle button for bots or quick reference, but does not enforce that players tell the truth in speech.
3. **5th Proposal ("Hammer") Rule**: In official Avalon rules, the 5th rejected proposal immediately awards victory to Evil. If a team is approved on the 5th proposal, the quest is executed normally.
4. **No `.sh` Scripts**: As dictated by repository rules, no `.sh` scripts will ever be utilized or created.

### 4.3 Authoritative Engine Architecture (`src/app/games/avalon/services/avalon-engine.service.ts`)

#### State Machine Flowchart:
```
[Lobby] ──createMatch()──> [Team Proposal]
                              ▲        │
                              │   proposeTeam()
                              │        ▼
                       reject │   [Team Voting]
                       (<5th) ├────────┬──────── approve
                              │        │
                     5th fail │        ▼
                     (Hammer) │   [Quest Execution]
                              │        │
                              ▼        ▼ submitQuestCard() (shuffled via CSPRNG)
                        [Evil Wins]    ├── 3 Fails ──> [Evil Wins]
                                       ├── 3 Passes ─> [Assassination Phase] (if Assassin active)
                                       │                      │
                                       │                      ├── Merlin hit ─> [Evil Wins]
                                       │                      └── Merlin missed -> [Good Wins]
                                       └── <3 Wins:
                                            ├── Quests 2,3,4 & Lady enabled ─> [Lady of Lake]
                                            └── Else ─────────────────────────> [Team Proposal] (Next Quest)
```

#### Core Engine Implementation Details:
1. **Role Deck Assembly & CSPRNG Assignment**:
   - Computes Good count `G` and Evil count `E` from `PLAYER_COUNT_RATIOS.get(numPlayers)`.
   - Good deck: Starts with `merlin`. If `roleConfig.percival` is enabled, adds `percival`. Fills remainder up to `G` with `loyal_servant`.
   - Evil deck: Starts with `assassin`. If `roleConfig.morgana` enabled, adds `morgana`. If `roleConfig.mordred` enabled, adds `mordred`. If `roleConfig.oberon` enabled, adds `oberon`. Fills remainder up to `E` with `minion`.
   - Uses cryptographic `crypto.getRandomValues()` (Fisher-Yates shuffle) to assign roles to seats `0..numPlayers - 1`.
   - Starting Leader: randomly selected in `0..numPlayers - 1`.
   - Lady of the Lake initial holder: seated immediately to the right of the first leader: `(startingLeader - 1 + numPlayers) % numPlayers`.

2. **Per-Seat State Sanitization (`getPlayerView`)**:
   ```typescript
   export function getNightVisionClues(
     players: AvalonPlayerState[],
     viewerSeat: number
   ): Map<number, NightVisionClue> {
     const clues = new Map<number, NightVisionClue>();
     const viewer = players.at(viewerSeat);
     if (!viewer) return clues;

     for (let i = 0; i < players.length; i++) {
       if (i === viewerSeat) {
         clues.set(i, 'self');
         continue;
       }
       const p = players.at(i);
       if (!p) continue;

       switch (viewer.role) {
         case 'merlin':
           // Merlin sees all Evil EXCEPT Mordred
           if (p.loyalty === 'evil' && p.role !== 'mordred') {
             clues.set(i, 'evil');
           } else {
             clues.set(i, 'unknown');
           }
           break;

         case 'percival':
           // Percival sees Merlin and Morgana, identical clue
           if (p.role === 'merlin' || p.role === 'morgana') {
             clues.set(i, 'merlin_or_morgana');
           } else {
             clues.set(i, 'unknown');
           }
           break;

         case 'assassin':
         case 'morgana':
         case 'mordred':
         case 'minion':
           // Evil players see each other EXCEPT Oberon
           if (p.loyalty === 'evil' && p.role !== 'oberon') {
             clues.set(i, 'evil_ally');
           } else {
             clues.set(i, 'unknown');
           }
           break;

         case 'oberon':
         case 'loyal_servant':
         default:
           // Oberon and Loyal Servants see nobody
           clues.set(i, 'unknown');
           break;
       }
     }
     return clues;
   }
   ```

3. **Fisher-Yates CSPRNG Quest Card Shuffle**:
   ```typescript
   export function shuffleQuestCards(cards: QuestCard[]): QuestCard[] {
     const result = [...cards];
     const randomBuffer = new Uint32Array(result.length);
     crypto.getRandomValues(randomBuffer);
     for (let i = result.length - 1; i > 0; i--) {
       const j = (randomBuffer.at(i) ?? 0) % (i + 1);
       const temp = result.at(i) ?? 'success';
       result[i] = result.at(j) ?? 'success';
       result[j] = temp;
     }
     return result;
   }
   ```

### 4.4 Deduction AI Bot (`src/app/games/avalon/services/avalon-bot.service.ts`)

The AI bot engine implements an autonomous Bayesian deduction model operating strictly from `AvalonPlayerView` (ensuring AI bots never cheat with host-internal state).

#### Mathematical Trust Model:
- For each player `i`, bot maintains `trustScores.set(i, score)` in `[-1.0, 1.0]`:
  - `+1.0`: Confirmed Good / Ally
  - `0.0`: Neutral prior
  - `-1.0`: Confirmed Evil / Adversary
- **Prior Initialization**:
  - `self` = `1.0`
  - If Bot is Evil (except Oberon):
    - Visible Evil allies = `1.0` (as teammates)
    - All other players = `-0.7`
  - If Bot is Merlin:
    - Players marked with `clue === 'evil'` = `-1.0`
    - Players marked with `clue === 'unknown'` = `0.3` (could be Mordred or Good)
  - If Bot is Percival:
    - The two `merlin_or_morgana` candidates start at `0.0` with 50/50 probability
    - Others start at `0.0`
  - If Bot is Loyal Servant or Oberon:
    - All opponents start at `0.0`

#### Dynamic Belief Updates:
1. **Quest Failure Penalty**:
   When Quest `k` fails with `F` fails and team `T`:
   - Every member of `T` receives trust penalty: `delta = -0.55 * (F / T.length)`.
   - If `F === T.length` (e.g. 2 fails on 2-person team), all members are confirmed evil (`trust = -1.0`).
2. **Voting Alignment Update**:
   - Players who voted `approve` on a team that subsequently failed: `delta = -0.25`.
   - Players who voted `reject` on a team that subsequently failed: `delta = +0.20`.
   - Players who voted `approve` on a team that succeeded: `delta = +0.15`.
3. **Lady of the Lake Verification**:
   - If the Bot is the investigator: private result is 100% ground truth (`Good -> +1.0`, `Evil -> -1.0`).
   - If another player investigated: the credibility of their claim is weighted by the investigator's existing trust score: `delta = investigatorTrust * claimWeight`.

#### Bot Decision Algorithms:

1. **Team Proposal (`proposeTeam`)**:
   - If Good:
     - Always include `viewerSeat`.
     - Rank other players by `trustScores` descending.
     - Pick top `teamSize - 1` players with highest trust scores (`trust > -0.2`).
   - If Evil:
     - If Hammer (Vote Track 4): Propose `self` + 1 evil ally (if needed) + highest-reputation Good players to force a failed quest.
     - Early game (Quests 1-2): Propose `self` + high-trust Good players. Avoid clustering multiple Evils on the same team to avoid suspicion.

2. **Proposal Voting (`voteProposal`)**:
   - **Hammer Priority**: If `voteTrack === 4` (the 5th proposal):
     - Good bots MUST vote `approve` (unless team is 100% confirmed Evil and loss is certain).
     - Evil bots vote `approve` if an Evil player is on the team; vote `reject` if team is purely Good to trigger instant Evil victory.
   - **Regular Proposal Evaluation**:
     - Calculates team average trust: `avgTrust = sum(trust(m)) / team.length`.
     - If Bot is on the team: `avgTrust += 0.25` (self-inclusion bias).
     - Threshold: Approves if `avgTrust >= 0.05`. Rejects if `avgTrust < 0.05`.

3. **Quest Card Play (`playQuestCard`)**:
   - If Good: ALWAYS `'success'`.
   - If Evil:
     - If this would be the 3rd failed quest: ALWAYS `'fail'` (immediate game win!).
     - If Quest 4 (requires 2 fails on 7+ players): ALWAYS `'fail'` if another Evil is on the team; `'fail'` with 85% probability if solo.
     - On Quest 1: 75% `'fail'`, 25% stealth `'success'` to establish deep cover.

4. **Lady of the Lake Target Selection (`chooseLadyTarget`)**:
   - Selects the eligible player with the highest uncertainty: `abs(trustScore)` closest to `0.0`.
   - If investigating Evil ally as an Evil bot: publicly claims "Good" to shield them.
   - If investigating Good player as Evil bot: claims "Evil" to frame them (or "Good" to bluff).

5. **Assassin Merlin Identification (`assassinateMerlin`)**:
   - Invoked when Good wins 3 quests. Evaluates all Good candidates.
   - Computes `merlinScore(candidate)`:
     - **Early Voting Precision**: Correlation between candidate's votes on Quests 1 & 2 and the true identities of Evil players (Merlin knows Evil from turn 1 without seeing quest results!).
     - **Proposal Purity**: Candidate never proposed an Evil player.
     - **Percival Disambiguation**: Detects whether the candidate played aggressively as a leader (likely Percival decoy) vs silently voting with uncanny accuracy (the real Merlin!).
   - Assassin selects candidate with highest `merlinScore`.

### 4.5 Component & UI Architecture

#### 1. Routing & Shell Integration
- Route paths:
  - `/avalon` -> redirects to `/avalon/lobby`
  - `/avalon/lobby` -> `AvalonLobbyComponent`
  - `/avalon/table` -> `AvalonTableComponent`
- Deep-link support: `?game=avalon&room=A1B2C3D4`

#### 2. Visual Theme: Arthurian Midnight / Crimson
- Palette tokens in `src/app/games/avalon/styles/_avalon-theme.scss`:
  - Background felt / table: `#070b14` to `#0d1527` (Arthurian Midnight)
  - Good banner / accent: `#1d4ed8` to `#3b82f6` (Royal Cobalt / Sapphire)
  - Evil banner / accent: `#991b1b` to `#dc2626` (Blood Crimson)
  - Excalibur / Quest Gold: `#d97706` to `#f59e0b`
  - Hammer alert: pulsating `#ef4444` border on Vote Track Slot 5

#### 3. Bounded Modals (Bottom-Only Actions)
Following `docs/reference/ui-conventions.md`:
- `QuestVoteModal`: Secret modal showing "Success" (blue crest) and "Fail" (red skull). For Good players, "Fail" is disabled with tooltip "Loyal servants cannot fail a quest".
- `LadyInvestigationModal`: Holder selects target, clicks "Investigate", and receives secret card flip revealing target's loyalty. Dismiss button at bottom.
- `AssassinationModal`: Evil Assassin selects target among Good players with confirmed assassination strike.
- `GameSummaryModal`: Final settlement modal revealing all players' true roles, quest breakdown, and winning condition.

#### 4. Hold / Toggle-to-Peek Privacy Shield Component
- `PrivacyShieldComponent` wraps player's private role card and night-vision clues.
- Default state: Opaque Arthurian Round Table crest.
- User action: `(pointerdown)="reveal()"` and `(pointerup)="conceal()"`, with an optional desktop "Toggle" checkbox for solo play.
- Touch/mouse leaving element conceals immediately, preventing accidental leaks.

#### 5. Responsive History Layout
- Desktop (`> 768px`): `<table class="desktop-table">` displaying Round #, Proposer, Nominated Team, Vote Breakdown badges (`Approve` / `Reject` per player), and Outcome.
- Mobile (`<= 768px`): `<div class="mobile-cards">` with expandable quest cards and color-coded status chips.
